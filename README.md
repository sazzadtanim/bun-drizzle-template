# replace-me-drizzle-app

Standalone drizzle-orm 1.0-rc + zod 4 + Bun template. The ONLY hand-edited
schema files are `src/lib/backend/drizzle/src/schema/*.ts` — everything else
(barrel, relations, zod schemas, browser barrel) is generated by `bun run gen`.
Chassis (auth/org/audit/settings) always ships; delete the domain layers you
do not need via `src/lib/backend/drizzle/docs/SAFE-DELETE.md`.

## Start

```sh
bun run init my_app my-app        # SCHEMA_NAME, package name, README title, .env
createdb my_app                   # then edit .env DATABASE_URL
bun install
bun run gen                       # barrel → relations → zod → biome
bun run db:generate               # first migration: creates every table in YOUR schema
bun run db:migrate                # apply it
bun run db:seed                   # REPLACE-ME chassis seed (see scripts/seed.ts)
bun run dev                       # http://localhost:3000
```

## Layout

```
server.ts                     app entry (Bun.serve): demo form + /api/health
init.ts                       one-time parameterizer (clone → init → done)
src/lib/backend/drizzle/
  drizzle.config.ts           migrations config (root-relative paths)
  env.ts                      SERVER-ONLY env parse (DATABASE_URL)
  drizzle/                    generated SQL migrations (drizzle-kit)
  docs/SAFE-DELETE.md         layer map + safe-delete guide
  src/
    index.ts                  server import surface (db, tables, relations, zod)
    schemas.ts                BROWSER-SAFE barrel (zod only — no env/db/pg)
    schema/                   ← the only hand-edited schema files
    zod-schemas/              GENERATED (gen) — refinements live in schema/
    relations.ts              GENERATED (gen) — FK graph, clean names
    schema.ts                 GENERATED (gen) — table barrel
    backup/                   vendored pg_dump backup/restore (no deps)
    scripts/                  gen pipeline + db:backup/restore/seed/replica
    __tests__/                regression suite (browser boundary, FK defaults…)
```

## Commands

| Command | What |
| --- | --- |
| `bun run gen` | regenerate barrel + relations + zod schemas + biome |
| `bun run gen:check` | CI staleness guard: `gen` + `git diff --exit-code` |
| `bun run db:generate` | drizzle-kit: write SQL migration from schema diff |
| `bun run db:migrate` | apply migrations |
| `bun run db:seed` | run the (hand-written, REPLACE-ME) seed |
| `bun run db:backup` / `db:restore` | pg_dump-based schema backup/restore |
| `bun run check` | tsc + biome |
| `bun run test` | regression suite |

## Conventions

- **Schema-only editing**: add a table module under `src/schema/`, re-run
  `gen`. Refinements are declarative (`<table>Refinements` export); Insert
  `id` is omitted unless the module exports `<table>ClientGeneratedIds`.
- **Browser boundary**: client code imports from `.../src/schemas` only.
  `env.ts`/`db.ts` are server-only — the browser-boundary test fails if that
  regresses.
- **Migrations are manual-review**: `db:generate` may prompt (renames/deletes
  are interactive drizzle-kit moments). `gen` never touches SQL.
